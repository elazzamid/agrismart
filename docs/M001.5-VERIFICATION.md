# M001.5 Authentication Verification

## Automated checks

Run from `backend/`:

```bash
go mod tidy
go test ./...
go build ./cmd/api
```

## Required integration checks

With PostgreSQL running and migrations applied:

1. Register a new farmer.
2. Verify exactly one `users` row and one `farmer_profiles` row are created.
3. Repeat registration with the same email and expect HTTP 409.
4. Verify an invalid email returns HTTP 400.
5. Verify a password shorter than 8 characters returns HTTP 400.
6. Login with the correct password and expect HTTP 200 with a Bearer access token.
7. Login with an incorrect password and expect HTTP 401.
8. Call `/api/v1/auth/me` with the token and expect HTTP 200.
9. Call `/api/v1/auth/me` without a token and expect HTTP 401.
10. Call `/api/v1/auth/me` with a malformed/invalid token and expect HTTP 401.

## Atomicity requirement

Registration must commit `users` and `farmer_profiles` together. If either insert fails, neither record may remain.

## Security requirements

- Plaintext passwords must never be persisted or returned.
- Password hashes use bcrypt.
- Authentication errors must not expose database errors or password details.
- JWT signing secret is supplied through environment configuration and must not be committed.
